# Pac-Man of Arrakis

## Description

**Pac-Man of Arrakis** is a complete, playable Pac-Man written in Python with
pygame, re-imagined in the deep desert of *Dune*. You play **Muad'Dib**, a
golden spice-eater with blue-within-blue eyes. You harvest **spice grains**
(pacgums) and **melange orbs** (super-pacgums) through mazes of sand dunes,
hunted by four Harkonnen: the **Baron**, **Rabban**, **Feyd** and a
**Sardaukar**. Eat melange and the Harkonnen turn Fremen-blue: catch them
and the sand swallows them for a few seconds.

The goal of the project is to build a full game with clean object-oriented
architecture:

- mazes generated by an **external A-Maze-ing package** (`mazegenerator`,
  used as-is, never modified);
- a **JSON configuration file with comments**, validated and clamped to safe
  defaults;
- a **persistent top-10 highscore** table;
- a polished UI: main menu, HUD, pause menu, game over / victory screens
  with name entry;
- a **cheat mode** for reviewers;
- a **packaged build** ready for itch.io.

Game loop: *Main Menu → Start Game → win or lose → enter your name →
back to the Main Menu.*

## Instructions

Requirements: Python 3.10 or newer and `make`.

```bash
make install      # create .venv, install pygame-ce + dev tools + the maze wheel
make run          # python3 pac-man.py config.json
make debug        # same, under pdb (and with tracebacks enabled)
make lint         # flake8 + mypy (mandatory flags)
make lint-strict  # flake8 + mypy --strict
make test         # pytest (unit tests of config, maze, highscores, rules)
make package      # PyInstaller build in dist/ + dist/pac-man-<os>.zip
make clean        # remove caches and build output
```

Run it by hand with exactly one argument, the configuration file:

```bash
.venv/bin/python pac-man.py config.json
```

Any problem with the command line or the file (wrong number of arguments,
missing file, invalid JSON) prints a clear `pac-man: error: ...` message and
exits with a non-zero status, never a traceback.

### Controls

| Key | Action |
| --- | --- |
| Arrow keys / W A S D | Move (a turn is remembered until it becomes possible) |
| P / Esc | Pause menu: *Resume* or *Main Menu* |
| Enter / Space or mouse click | Confirm in menus (the mouse can also hover to select) |
| F1 | Toggle cheat mode |

### Cheat mode

Press **F1** during a game (or set `"cheat_mode": true`). The HUD footer
turns orange and lists the cheats:

| Key | Cheat |
| --- | --- |
| I | Invincible: ghosts and the timer cannot take a life |
| F | Freeze the ghosts |
| V | Speed boost for the player |
| L | Extra life |
| N | Skip the level (instant win; skipping the last level wins the game) |
| T | Refill the level timer |

### Rules

- The player starts in the middle of the maze with `lives` lives. Ghosts
  start in the four corners, on top of the four super-pacgums.
- Pacgums give `points_per_pacgum`. Super-pacgums give
  `points_per_super_pacgum` and make the ghosts edible for
  `frightened_time` seconds (they flash just before the end). An edible
  ghost gives `points_per_ghost` and comes back to its corner after
  `ghost_respawn_time` seconds.
- Touching a ghost costs a life. Everyone goes back to their spawn.
- **Time limit:** when a level's timer reaches 0 you lose a life and the
  timer starts again (pacgums already eaten stay eaten).
- Eat every pacgum to clear the level. Score and lives carry over. Clearing
  the last level wins the game; losing the last life ends it.

## Configuration

`config.json` is standard JSON plus comments: lines starting with `#`, `//`
line comments and `/* ... */` blocks are ignored (outside strings). Every key
is optional. A missing, mistyped or out-of-range value is replaced by its
default (or clamped to the nearest bound), a warning is printed in the
terminal, and the main menu shows how many warnings happened. Unknown keys
are ignored with a warning. Only an unreadable file or broken JSON stops the
program.

| Key | Default | Range | Meaning |
| --- | --- | --- | --- |
| `highscore_filename` | `"highscores.json"` | non-empty string | Highscore file. A relative path is relative to the config file. |
| `lives` | `3` | 1 – 99 | Starting lives |
| `points_per_pacgum` | `10` | 0 – 1 000 000 | Score for a pacgum |
| `points_per_super_pacgum` | `50` | 0 – 1 000 000 | Score for a super-pacgum |
| `points_per_ghost` | `200` | 0 – 1 000 000 | Score for an edible ghost |
| `seed` | `42` | 1 – 2³¹−1 | Seed of the first level's maze |
| `level_max_time` | `120` | 10 – 3600 s | Default time limit of a level |
| `pacgum` | `0` | 0 – 100 000 | Max pacgums per level, `0` = one on every free corridor tile |
| `player_speed` | `8.0` | 1 – 20 tiles/s | Player speed |
| `ghost_speed` | `5.5` | 1 – 20 tiles/s | Ghost speed on level 1 |
| `ghost_speed_step` | `0.15` | 0 – 2 tiles/s | Ghost speed added on each level |
| `frightened_time` | `7` | 1 – 60 s | How long ghosts stay edible |
| `ghost_respawn_time` | `5` | 0.5 – 60 s | Delay before an eaten ghost comes back |
| `cheat_mode` | `false` | boolean | Start with cheat mode enabled |
| `window_width` / `window_height` | `1280` / `800` | 640–3840 / 480–2160 | Window size (the maze scales to fit) |
| `fps` | `60` | 30 – 240 | Frame rate cap |
| `levels` | 10 default levels | array | The campaign, see below |

Each entry of `levels` is an object:

| Key | Default | Range | Meaning |
| --- | --- | --- | --- |
| `width`, `height` | from the default campaign | 5–45, 5–35 | Maze size in generator cells (the "42" needs at least 14×10) |
| `seed` | random | 0 – 2³¹−1 | Fixed seed for this level (`0` = random) |
| `level_max_time` | global `level_max_time` | 10 – 3600 s | Time limit of this level |
| `pacgum` | global `pacgum` | 0 – 100 000 | Max pacgums in this level |

The first level always uses a fixed seed: its own `seed`, or the global
`seed`. The other levels are random unless they set a seed. Invalid level
entries are skipped. If fewer than 10 valid levels remain, default levels
are appended so the game always has at least 10.

Each maze cell is drawn as a 2×2 block of tiles, so a 15×11 maze is 31×23
tiles. The default times (120 s → 240 s) grow with the maze sizes so that
every level can be cleared.

## Highscore

- **Storage:** a JSON array of `{"name": ..., "score": ...}` in the file
  named by `highscore_filename`, next to the config file by default. A
  human-readable file next to the game is easy to inspect, reset or edit
  during a review, and it also works in the packaged build (the itch.io
  install folder is writable).
- **Loading:** at start-up. A missing file means an empty table. A
  corrupted file (bad JSON, not an array, unreadable) is reported in the
  terminal and on the main menu, and the game continues with an empty
  table. Invalid entries are skipped one by one: a name that is not 1–10
  letters, digits or spaces, or a score that is negative or not an integer.
- **Saving:** at the end of every game, after the player types a name. The
  table is written to a temporary file first and then atomically renamed
  over the old one, so a crash can never leave a half-written file. If
  writing fails, the menu says so and the game keeps running.
- **Rules:** names are 1–10 characters (letters, digits, spaces; extra spaces
  are collapsed), scores are non-negative integers. Only the 10 best scores
  are kept, best first; a tie keeps the older score in front.
- **Display:** the best score is shown on the main menu, and the whole top
  10 is under *Highscores*.

## Maze Generation

Levels come from the assigned A-Maze-ing package, shipped as
`mazegenerator-00001-py3-none-any.whl` at the repository root and installed
untouched by `make install`. Its interface:

```python
from mazegenerator import MazeGenerator
gen = MazeGenerator(size=(width, height), perfect=False, seed=seed)
gen.maze  # list of rows; each cell is an int whose bits are its walls
          # N=1, E=2, S=4, W=8
```

`pacman/maze.py` is the only module that knows about the package. It adapts
to that interface as follows:

1. **Calling it:** `PERFECT` is always `False`, which gives loops and
   Pac-Man-friendly corridors. The seed is always positive (the package
   treats `0` as "random"), so every maze can be reproduced from the seed
   that made it. The first level uses the configured seed (42 by default),
   and later levels draw a random seed.
2. **Recursion:** the package carves the maze with one recursive call per
   cell. Mazes bigger than about 40×30 would exceed Python's default
   recursion limit, so the adapter raises the limit while it runs and puts
   it back afterwards.
3. **Its prints:** the package prints warnings, for example when a maze is
   too small for the "42". These are captured and logged instead of
   cluttering the terminal.
4. **Validation:** the result must be a rectangular grid of ints with the
   requested size.
5. **Cells to tiles:** cell `(x, y)` becomes tile `(2x+1, 2y+1)`. The tile
   between two cells is a corridor when neither cell has a wall on that
   side, and every other tile is a wall. Fully closed cells (the "42" the
   package draws in the middle) become `BLOCK` tiles. They are drawn as
   solid sietch rock with glowing spice veins, so the 42 stays visible in
   every level.
6. **Failures:** if the package raises an exception, returns garbage or is
   not installed, the adapter retries with up to 3 seeds. After that it
   raises a `MazeError`. The UI then shows a "the desert refused to form a
   maze" screen and returns to the main menu, without crashing.

The level builder then places the player on the floor tile nearest the
centre. It puts the 4 super-pacgums and the 4 ghost homes on the floor tiles
nearest the 4 corners, and the pacgums on every other tile reachable from
the spawn (or a seeded sample of them when `pacgum` is set).

## Implementation

- **Movement:** actors move tile-centre to tile-centre. Each one stores the
  tile it is leaving, the tile it is entering and a progress value from 0
  to 1. This gives smooth movement at any speed while keeping collisions
  with walls exact. The player's last requested turn is buffered and
  applied at the first tile where it is possible. Reversing is applied
  immediately.
- **Ghost AI** (`pacman/ai.py`): at each tile centre a ghost picks an open
  direction, avoiding U-turns except in dead ends. It takes the direction
  with the shortest **BFS walking distance** to its target, which works much
  better than straight-line distance in a maze. The targets follow the
  classic personalities:
  - *Baron:* the player.
  - *Rabban:* 4 tiles ahead of the player.
  - *Feyd:* sometimes a random tile.
  - *Sardaukar:* chases from afar, retreats to its corner when close.

  Ghosts alternate between scatter (5 s) and chase (20 s). When frightened,
  they move slower and maximise their distance from the player, with some
  randomness.
- **Collisions:** distance between interpolated positions below 0.6 tiles,
  plus a "crossed each other" check, so fast actors cannot pass through
  each other in one frame. Frame time is capped at 1/30 s.
- **Timing:** everything uses `dt` (seconds), so the game speed does not
  depend on the frame rate.
- **Robustness:**
  - Config errors are clamped (see above).
  - Highscore I/O never raises.
  - Maze failures become an error screen.
  - The window losing focus auto-pauses the game.
  - `cli.main` catches everything else and prints a one-line message (set
    `PACMAN_DEBUG=1` to get the traceback).
  - Files are always opened through context managers.
- **Graphics:** everything is drawn with pygame primitives: the dune walls
  (drawn in three passes: shadow, body, crest), the rippled sand, the
  glowing spice, Muad'Dib, the Harkonnen and the night desert with its two
  moons. The game ships no image, sound or font asset. The static maze is
  rendered once per level into a cached surface.
- **Quality:**
  - `flake8` clean.
  - `mypy` clean with the mandatory flags and with `--strict`.
  - Docstrings on every module, class and function.
  - 36 pytest tests. The game rules are tested headless because
    `GameSession` does not depend on pygame.

## General Software Architecture

```
pac-man.py            entry point -> pacman.cli.main(sys.argv)
pacman/
  cli.py              argument check, config loading, top-level error handling
  config.py           JSON-with-comments parser, GameConfig / LevelConfig, clamping
  maze.py             A-Maze-ing adapter: MazeGenerator -> TileMap, MazeError
  level.py            Level: spawns, corners, pacgums built from a TileMap
  entities.py         Direction, Mover (tile interpolation), Player, Ghost, GhostMode
  ai.py               ghost personalities and BFS-based direction choice
  game.py             GameSession: rules, score, lives, timer, phases, cheats
  highscores.py       HighscoreTable: load / validate / add / atomic save
  theme.py            Dune palette, fonts, procedural sprites and backdrop
  render.py           BoardRenderer (cached maze, actors, banners) and HUD
  scenes.py           MainMenu, Highscores, Instructions, Game (+pause), End, Error
  app.py              App: window, main loop, active scene, shared highscores
tests/                pytest suite (headless)
pac-man.spec          PyInstaller spec (build + itch.io zip)
packaging/            files shipped next to the executable
project_management/   planning, choices, risks, test plan
```

How the pieces fit together:

- `App` owns the window and the `HighscoreTable`. It runs the loop: events,
  then `update(dt)`, then `draw()` on the active `Scene`.
- `GameScene` wraps a `GameSession` (pure logic) and a `BoardRenderer`
  (pure drawing).
- `GameSession` builds each `Level` with `build_level()`, which calls
  `load_maze()`, the only place that talks to the external package.
- The logic layer (`config`, `maze`, `level`, `entities`, `ai`, `game`,
  `highscores`) never imports pygame. Only `theme`, `render`, `scenes` and
  `app` do.

## Packaging and deployment

`make package` runs PyInstaller with `pac-man.spec`. It produces:

- `dist/pac-man/`: the executable plus `config.json`, `HOW_TO_PLAY.txt`
  (the in-package instructions), `play.sh` / `play.bat` launchers, and an
  `.itch.toml` manifest that makes the itch.io app start the game with
  `config.json`;
- `dist/pac-man-<os>.zip`: the archive to upload.

PyInstaller does not cross-compile, so build on each target OS. Upload the
zip to a **Draft / restricted** itch.io page (free, unlisted), either with
the web uploader or with
`butler push dist/pac-man-linux.zip <user>/pac-man-of-arrakis:linux`.
